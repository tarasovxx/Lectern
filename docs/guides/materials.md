# Конспекты и тесты

Генерация материалов подключается к готовому транскрипту. Локальную модель можно запустить вместе с приложением на NVIDIA GPU или подключить отдельный сервер. Облачный режим выбирается явно.

## Запустите распознавание и генерацию на NVIDIA GPU

Нужны Linux, NVIDIA GPU, рабочий драйвер и NVIDIA Container Toolkit. Подготовьте HF_TOKEN по [руководству локальной обработки](local.md). Имя модели задаёт LOCAL_LLM_MODEL в .env; по умолчанию используется qwen2.5:7b. Качество её педагогических выводов и запуск LEctern на реальном GPU пока не проверены.

```sh
nvidia-smi
make stop
make gpu-materials
```

Команда объединяет compose.yaml, compose.gpu.yaml и compose.ollama.yaml. Speech распознаёт речь на GPU, а контейнер Ollama принимает запросы генерации через ml. Его адрес http://ollama:11434/v1 доступен только внутри Compose; порт 11434 на хост не публикуется. В этом режиме значение LOCAL_LLM_URL из .env не используется. Groq и Gemini не вызываются; облачные функции Ollama отключены.

Первый запуск скачает образы и выбранную модель Ollama. Сервис ollama-init выполняет её загрузку до запуска ml. Веса речевых моделей загружаются при первом запросе. При следующих запусках ollama-init использует модель из кеша без повторной загрузки. Кеши model-cache и ollama-data сохраняются после make stop.

Ollama держит в памяти не более одной модели и выполняет один запрос за раз. После ответа модель выгружается из памяти. Речевые модели остаются в speech, поэтому свободная видеопамять для генерации не гарантирована. Проверку размещения модели описывает [раздел о видеопамяти](../operations/troubleshooting.md#gpu-memory).

Откройте /api/config: ожидаются local и generate_materials: true. Загрузите запись и проверьте транскрипт, конспект и тест.

## Подключите отдельный локальный сервер

Запустите сервер с OpenAI-совместимым маршрутом /v1/chat/completions, например Ollama. Модель должна быть установлена на этом сервере заранее. Установка Ollama описана в [официальном руководстве](https://docs.ollama.com/quickstart); для подключения нужен её [локальный API](https://docs.ollama.com/api/openai-compatibility#local-server-usage).

В файле .env задайте:

```dotenv
LOCAL_LLM_URL=http://host.docker.internal:11434/v1
LOCAL_LLM_MODEL=qwen2.5:7b
```

Имя модели должно совпадать с установленным. Значение в примере — текущая настройка по умолчанию; качество её педагогических выводов не проверено. Адрес host.docker.internal ведёт из контейнера на хост Docker. На Linux сервер должен принимать соединения из контейнеров.

Команда make materials использует CPU для распознавания речи. Подготовьте также HF_TOKEN по [руководству локальной обработки](local.md), затем запустите:

```sh
make stop
make materials
```

Откройте /api/config: ожидаются local и generate_materials: true. После обработки доступны транскрипт, локальные показатели, конспект и тест. Ошибка генерации не требует повторного распознавания, если транскрипт уже сохранён: используйте повторную генерацию в интерфейсе.

## Включите облачный режим

Этот режим отправляет аудио в Groq, а текст — в Gemini. Выбирайте его только для записей, которые разрешено передавать этим провайдерам.

Заполните в .env:

```dotenv
GROQ_API_KEY=...
GEMINI_API_KEY=...
GEMINI_GENERATION_MODELS=...
```

В последнем поле укажите идентификатор доступной вашему аккаунту модели Gemini. Затем выполните:

```sh
make stop
make cloud
```

Для этого режима speech не нужен. Определение говорящих и ролей через локальный pyannote здесь не выполняется. Автоматического переключения из локального режима в облако нет.
