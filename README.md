# LEctern

Запись занятия → расшифровка с ролями и таймкодами → показатели участия. Конспекты, тесты и анализ речи из AdaptiveEducation подключаются отдельно.

## Запустить демо

Нужны Docker с запущенным сервером и Docker Compose v2.30+.

```sh
cp .env.example .env
make demo
```

Откройте http://localhost:8090 и загрузите небольшой файл. Демо возвращает заранее заданный синтетический транскрипт независимо от содержимого файла. Оно проверяет интерфейс, очередь и сохранение результатов. Модели и ключи не нужны. В интерфейсе режим помечен явно.

```sh
make logs   # логи сервисов
make stop   # остановка с сохранением базы и моделей
```

## Обработать свою запись локально

1. Создайте Read-токен Hugging Face. Под тем же аккаунтом примите условия моделей [speaker-diarization-community-1](https://huggingface.co/pyannote/speaker-diarization-community-1) и [segmentation-3.0](https://huggingface.co/pyannote/segmentation-3.0).
2. Укажите токен в поле HF_TOKEN файла .env.
3. Запустите нужный вариант:

```sh
make local  # CPU: без NVIDIA, медленнее
make gpu    # Linux + NVIDIA GPU + NVIDIA Container Toolkit
```

Первый запуск скачает образы, Whisper и pyannote. Следующие запуски используют кеш моделей. Для автономной работы сначала подготовьте образы и веса при доступном интернете. Аудио при локальной обработке не отправляется в Groq или Gemini. Речевой контейнер закреплён на Linux x86_64 из-за доступности TorchCodec. На Mac с Apple Silicon нужен запуск через эмуляцию x86_64; этот вариант и его скорость ещё не проверены. Демо на Mac не требует речевого контейнера. GPU-вариант требует NVIDIA.

Запись поступает в речевой сервис целиком. Разделение говорящих выполняется на всём файле. Веб показывает транскрипт, роли и числовые показатели без LLM. В текущем вебе сохранился лимит загрузки 200 МБ; для длинного видео сначала выделите аудио:

```sh
ffmpeg -i lesson.mp4 -vn -ac 1 -ar 16000 -b:a 64k lesson.mp3
```

Контейнер речевого сервиса не публикует свой порт наружу. Временная запись удаляется после обработки, результат хранится в базе веба. Результат можно удалить из истории. Проверка F1 и скорости на реальном GPU ещё нужна.

## Добавить конспекты и тесты

Поднимите локальный сервер с OpenAI-совместимым API, например Ollama. Укажите его адрес и установленную модель в LOCAL_LLM_URL и LOCAL_LLM_MODEL файла .env. Значение по умолчанию — qwen2.5:7b; качество педагогических выводов для неё не проверено.

```sh
make materials
```

Адрес host.docker.internal ведёт на хост с Docker. На Linux сервер модели должен принимать соединения из контейнеров. Этот режим обрабатывает речь локально и передаёт транскрипт указанному локальному серверу генерации. При его ошибке сохранённая расшифровка доступна для повторной генерации.

Для облачного варианта заполните GROQ_API_KEY, GEMINI_API_KEY и GEMINI_GENERATION_MODELS в .env, затем выполните:

```sh
make cloud
```

В этом режиме аудио отправляется в Groq, а текст — в Gemini. Автоматического переключения из локального режима в облачный нет. Возможности аккаунта и доступность выбранной модели проверяются при реальном запросе.

## Что находится в репозитории

| Каталог | Источник | Назначение |
|---|---|---|
| services/web | AdaptiveEducationWeb | Интерфейсы преподавателя и ученика, SQLite, очередь, конспекты и тесты |
| services/ml | AdaptiveEducationML | Генерация через локальный API или Gemini, облачное распознавание через Groq |
| services/speech | yadrovichi | faster-whisper, pyannote, роли говорящих, аналитика и экспорт |

Происхождение файлов и ревизии записаны в [sources.json](docs/sources.json). Исходные README оставлены внутри сервисов: команды из них относятся к отдельным проектам. Для LEctern используйте команды этого README.

## Проверить изменения

Для разработки нужен Python 3.11 или 3.12. Тесты не скачивают модели и не требуют GPU.

```sh
python3 -m venv .venv
. .venv/bin/activate
pip install -r requirements-dev.txt
make test
make config
python scripts/smoke.py  # при работающем make demo
```

Три набора тестов запускаются в отдельных процессах: у двух сервисов Python-пакет называется app. CI проверяет тесты, конфигурацию Compose, сборку веба и ML, затем HTTP-сценарий демо.

Это начальная интеграция. Согласованная таксономия пяти методических приёмов, рекомендации с проверенными фрагментами, оценка каждого вывода пользователем и подтверждённые F1/RTF остаются следующими этапами. [Материалы для них](docs/materials.md).
